Retail Brain OS — Run Guide

1. Purpose

This repository contains the current verified Retail Brain OS MVP.

The current working product is the Edge Runtime desktop application with:

live camera input

person detection

persistent tracking

configurable zones

zone entry/exit intelligence

dwell-time intelligence

live dashboard

active-person selection

selected-person details

surveillance recording

face capture

session/person data saving

saved-file browser

responsive desktop GUI

product-style dark visual theme

live system-status footer

This document is the practical handoff guide for installing and running the current MVP.

2. Important Architecture Note

The current GUI is a Tkinter desktop application.

The current MVP is not a browser-native web application.

The main application flow is:

Retail Brain OS GUI
        |
        v
RetailVisionRuntime
        |
        +--> Camera
        +--> Detector
        +--> Tracker
        +--> Zone Engine
        +--> Retail Intelligence Engine
        |
        v
Live Dashboard

The GUI owns presentation and user controls. The RetailVisionRuntime owns the camera, detector, tracker, zone engine and intelligence engine.

The production/web deployment layer is intentionally a separate responsibility.

3. Supported Development Baseline

The project was developed and verified with:

Windows 10/11 x64

Python 3.11.x

Conda environment named retail_OS

NVIDIA GPU is supported by the project dependency baseline

CPU execution is also part of the planned deployment matrix

The dependency baseline documented for the project specifies Python 3.11.9 and supports Windows 10/11 Pro x64, Windows Server, Ubuntu 22.04 LTS and Ubuntu 24.04 LTS.

For this exact GUI MVP, Windows is the safest reproduction environment because the current Tkinter/OpenCV camera workflow was verified there.

5. Clone / Download

Git

Clone the repository:

git clone <REPOSITORY_URL>
cd RetailBrainOS

Then enter the Edge Runtime:

cd edge-runtime

If the repository is delivered as a ZIP instead, extract it and open a terminal in:

RetailBrainOS\edge-runtime

6. Create the Conda Environment

Create the environment:

conda create -n retail_OS python=3.11

Activate it:

conda activate retail_OS

Verify:

python --version

Expected:

Python 3.11.x

7. Install Dependencies

From:

RetailBrainOS\edge-runtime

run:

pip install -r requirements.txt

The project dependency baseline includes the major runtime components used by the broader Retail Brain OS foundation, including:

FastAPI

Uvicorn

Pydantic

SQLAlchemy

Alembic

psycopg

Redis client

HTTPX

structlog

NumPy

OpenCV

Ultralytics

PyTorch

torchvision

torchaudio

ONNX Runtime

Do not casually upgrade these dependencies before deployment. The project uses a controlled dependency baseline.

8. Verify the Installation

Before launching the GUI, compile the relevant packages:

python -m compileall app\gui

Then:

python -m compileall app\intelligence

There should be no syntax errors.

9. Run the Existing Intelligence Tests

Run the integration test:

python -m app.intelligence.test_intelligence_engine

Expected:

Frame 1 - Outside        : PASS
Frame 2 - Entry          : PASS
Frame 3 - Dwell 30s      : PASS
Frame 4 - Exit           : PASS

SUCCESS

Run the dwell-session test:

python -m app.intelligence.test_dwell_session

Expected:

Zone A dwell (30s) : PASS
Zone B dwell (45s) : PASS
Total dwell (75s)  : PASS
First seen         : PASS

Run the B-4.9 exit regression test:

python -m app.intelligence.test_intelligence_exit_B49

Expected:

Zone entry                : PASS
Visible zone exit         : PASS
Camera-sight disappearance: PASS
Grace-period protection   : PASS
CUSTOMER_EXIT events      : PASS

SUCCESS

The B-4.9 test specifically verifies that a person leaving a zone and a person disappearing from camera sight can both produce CUSTOMER_EXIT.

10. Start Retail Brain OS

Run:

python -m app.gui.retail_os_gui

The Tkinter application should open.

The current GUI has a minimum size around:

1000 x 650

and the working normal size is around:

1200 x 750

11. First-Time Runtime Workflow

When the GUI opens:

SETUP ZONES
     |
     v
Create / edit zones
     |
     v
Close Zone Setup
     |
     v
START RETAIL OS

The configured zones are persisted through the project's zone configuration.

The runtime loads the zone configuration when Retail OS starts.

Zone editing is intentionally restricted while the runtime is running.

12. Live Runtime Workflow

After pressing:

START RETAIL OS

the runtime starts asynchronously.

The GUI then polls runtime state and displays:

live camera frames

FPS

runtime status

camera status

tracker status

zone count

live intelligence

current active people

dwell information

recent events

The camera itself is not owned by the dashboard.

14. Data Locations

The current GUI uses application-relative directories for generated data.

Surveillance

recordings/

Face captures

face_captures/

Session exports

data_exports/

Selected-person data

person_data/

These are runtime-generated directories.

They should not normally be committed with large generated recordings or test data.

15. Camera Requirements

The current camera/display configuration uses OpenCV.

The project camera baseline includes:

Camera index: 0
Preferred capture resolution: 1280 x 720
Initial OpenCV window size: 1280 x 720

The actual frame returned by OpenCV remains authoritative for coordinate calculations.

The current MVP has been verified with a local camera.

For production multi-store deployment, camera/Edge Agent handling is a separate deployment concern.

16. GPU / Model Requirements

The broader project dependency baseline specifies:

CUDA Toolkit: 12.4
NVIDIA Driver: >= 550.xx
PyTorch: CUDA 12.4 compatible build
Ultralytics: 8.3.0

The exact model file used by the current runtime must also be present wherever the current runtime configuration expects it.

Do not invent or change the model path during handoff.

If the model file is not included in Git, the deployment owner must supply it through the project's model/deployment process.

17. Environment Variables / Secrets

Never commit real secrets.

Do not commit:

.env

if it contains passwords, tokens, API keys or database credentials.

Use:

.env.example

for configuration templates.

18. What Not To Commit

Do not commit:

__pycache__/
*.pyc
.venv/
.env
large recordings
temporary face captures
temporary exports
debug output
experimental backup scripts

Do not deploy an intermediate backup such as:

*_backup.py

as the canonical production file.

The repository should contain one authoritative version of each production module.
